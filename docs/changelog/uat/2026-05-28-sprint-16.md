## What Changed

Sprint 16 was a major UI overhaul sprint. It introduced a new **Home** page with
stat cards, a Projects section, and an Activity feed; rebuilt the **Sprint Mgmt**
tab with a toolbar, a reusable sprint block component, a live log viewer, and a
sticky Backlog block; added per-ticket and sprint time tracking; enforced a pytest
gate in the Tester agent before any merge; and added a TRAVEL_PLAYBOOK.md for
iPad-only remote access.

## What to Test

### Checklist

- [ ] **#182 — Tester pytest gate**
  - Where to look: Tester agent run for any feature branch
  - Happy path: tester runs pytest and only merges to develop on a green test suite
  - Edge cases: a branch with no test file should fail the gate and stay at SIT

- [ ] **#212 — Time tracking**
  - Where to look: Sprint Mgmt tab → each sprint card; individual ticket rows
  - Happy path: each ticket shows elapsed time; sprint block header shows total sprint time
  - Edge cases: time should update live while a sprint is running

- [ ] **#213 — Sprint goal field hidden**
  - Where to look: Sprint Mgmt → sprint block form / settings
  - Happy path: no sprint goal input field visible; no 10-char validation error triggered
  - Edge cases: creating a new sprint should succeed without entering a goal

- [ ] **#216 — GET /api/home**
  - Where to look: `GET http://localhost:8001/api/home`
  - Happy path: returns `stats`, `projects`, and `activity` keys; per-project data present
  - Edge cases: endpoint returns HTTP 200 even when no projects are tracked

- [ ] **#218 — Home Projects section**
  - Where to look: Home tab → Projects section
  - Happy path: active projects appear as cards; idle projects appear in a collapsed deck
  - Edge cases: repos with no open issues should show as idle

- [ ] **#219 — Home Activity feed**
  - Where to look: Home tab → Activity feed
  - Happy path: last 5 agent events appear with timestamps and event types
  - Edge cases: feed shows "No recent activity" when the event table is empty

- [ ] **#220 — Routing rename**
  - Where to look: `http://localhost:8001/` — should load the Home page
  - Happy path: root route `/` renders the new Home page; no "Overview" label visible in nav
  - Edge cases: deep links like `/projects/foo/bar` should still route to the project page

- [ ] **#221 — Persistent project sidebar**
  - Where to look: click any project card → project detail view
  - Happy path: sidebar shows project list; selecting a project shows sub-tabs (Sprint Mgmt, Agents, etc.) without a full page reload
  - Edge cases: refreshing on a project sub-tab should restore the correct project and tab

- [ ] **#222 — Sprint Mgmt toolbar**
  - Where to look: Sprint Mgmt tab → top toolbar
  - Happy path: Trigger Refresh, New Ticket, and New Sprint buttons are visible; clicking New Sprint opens a modal; clicking New Ticket opens the draft ticket modal
  - Edge cases: Trigger Refresh should re-fetch sprint data without a full page reload

- [ ] **#223 — Sprint block four visual states**
  - Where to look: Sprint Mgmt tab → individual sprint cards
  - Happy path: sprint blocks show distinct visual states for idle, running, completed, and failed
  - Edge cases: a blocked sprint should show the correct blocked state, not idle

- [ ] **#224 — Live log panel**
  - Where to look: Sprint Mgmt tab → running sprint block → log panel below
  - Happy path: live log lines appear while the sprint is running; Refresh button reloads the tail; Cancel button stops the sprint
  - Edge cases: log panel should show "No log yet" when the sprint just started

- [ ] **#225 — Sticky Backlog block**
  - Where to look: Sprint Mgmt tab → bottom of the sprint list
  - Happy path: Backlog block stays at the bottom even after reordering sprint blocks via drag-and-drop
  - Edge cases: Backlog block should not appear in the middle of the list after a page refresh

- [ ] **#231 — TRAVEL_PLAYBOOK.md**
  - Where to look: `docs/TRAVEL_PLAYBOOK.md`
  - Happy path: file exists and contains pre-travel checklist, remote recovery steps, and SSH command reference
  - Edge cases: links from README.md to the playbook should not 404
