## What Changed

Sprint 6 shipped three sprint management improvements: inline run/kill controls
on each sprint card, a fix that stopped the manager from auto-creating junk
empty sprints, and a fix for stale stub-run summaries being treated as valid
(causing fresh summaries to be silently skipped).

### Features & Fixes

| Issue | Title | Type |
|---|---|---|
| #110 | Sprint Mgmt: inline Run/Kill buttons per sprint card with live progress | feature |
| #111 | Sprint Mgmt: stop auto-creating empty sprint placeholders (sprint-99, sprint-100, etc.) | fix |
| #114 | bug: sprint manager treats stale stub-run summary issues as valid, skipping fresh summaries | fix |

## What to Test

### Checklist

- [ ] **#110 — Inline Run/Kill buttons**
  - Where to look: Sprint Mgmt tab → any sprint card
  - Happy path: each sprint card shows a **Run** button when idle and a **Kill** button when running; progress counter updates without page refresh
  - Edge cases: clicking Run twice should not double-start; Kill during a running sprint should terminate cleanly and show a stopped state

- [ ] **#111 — No empty sprint placeholders**
  - Where to look: Sprint Mgmt tab → sprint list
  - Happy path: no `sprint-99`, `sprint-100`, or other synthetic placeholder labels appear after a sprint run
  - Edge cases: run a sprint, let it finish, check GitHub labels — no new empty sprints should exist

- [ ] **#114 — Stale stub-run detection**
  - Where to look: `.commander/sprints/` folder and the sprint summary GitHub issue
  - Happy path: when a sprint finishes for the second time, the summary issue is updated in place rather than a duplicate being created or the update being skipped
  - Edge cases: manually set a summary issue to a stub state and rerun — should detect and overwrite
