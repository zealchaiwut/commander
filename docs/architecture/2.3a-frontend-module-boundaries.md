# 2.3a — Frontend module boundaries

> **Status:** canonical module map for the `project.html` strangler-fig extraction
> (issue #796 / #797). Documentation + incremental extraction — same pattern as
> [boundaries.md](./boundaries.md) for the backend.

## Layer rules

1. **ES modules** live under `apps/dashboard/static/src/`. Each module `export`s
   functions; the sprint-board barrel (`sprint-board/index.js`) re-attaches
   public handlers to `globalThis` so inline HTML (`onclick`, `ondrag*`) keeps
   working without a framework.
2. **`static/dist/bundle.js`** is the committed esbuild IIFE output. Run
   `npm run build` after editing `static/src/`; the dashboard serves the bundle
   from disk with no runtime build step.
3. **`project.html`** retains markup, tab shells, and inline JS not yet
   extracted. New sprint-board logic must land in `static/src/sprint-board/`,
   not inline.

1. **Sprint-board concerns** — in progress; seed complete for board/drag/modals/plan-next/schedule
2. **Shell** — tab routing, theme, URL parsing (few cross-tab deps)

4. **Bulk-create** — self-contained tab
5. **Deploy / settings / metrics** — more API surface, extract after shell
