## What Changed

Sprint 20 was a Sprint Management board polish sprint, targeting the current-UI
(`project.html`). It restored several visual and interactive features that had
regressed since the sprint-16 rewrite, and added two new board capabilities:
a Backlog pane and an auto-refresh countdown pill.

## What to Test

### Checklist

- [ ] **#272 — New Ticket buttons open current UI form**
  - Where to look: project page → "＋ New ticket" header link and Sprint Mgmt toolbar "New Ticket" button
  - Happy path: clicking either button opens the in-page new-ticket modal (not the legacy `/legacy/` UI)
  - Edge cases: submitting the modal should create a GitHub issue and show a confirmation without a full page reload

- [ ] **#273 — Empty sprint panes visible as drop targets**
  - Where to look: Sprint Mgmt tab → any sprint that has zero tickets
  - Happy path: empty sprint renders its full pane (title, Delete button, disabled Run button); tickets can be dragged into it
  - Edge cases: deleting all tickets from a sprint should keep the pane visible; adding a ticket back should populate the pane normally

- [ ] **#274 — Backlog pane in Sprint Management board**
  - Where to look: Sprint Mgmt tab → below all sprint blocks
  - Happy path: Backlog pane lists all issues with the `backlog` label; tickets can be dragged from Backlog into a sprint pane
  - Edge cases: assigning a backlog ticket to a sprint should remove the `backlog` label; pane should show "No backlog items" when empty

- [ ] **#275 — Auto-refresh countdown pill**
  - Where to look: Sprint Mgmt toolbar — where "Trigger Refresh" button used to appear
  - Happy path: countdown pill shows seconds until next auto-refresh; board data refreshes automatically when it reaches zero; clicking the pill triggers an immediate refresh and resets the timer
  - Edge cases: countdown should pause if a move is in flight; pill should resume after the overlay clears

- [ ] **#276 — Spinner overlay during ticket move**
  - Where to look: Sprint Mgmt board → drag a ticket between panes or use the "Move to" dropdown
  - Happy path: a full-board loading overlay appears for the duration of the move and disappears once the GitHub label write completes
  - Edge cases: a second move attempt while the overlay is active should be blocked (cursor change / click-through disabled); overlay must clear on API error so the board is not permanently locked

- [ ] **#277 — Animated live treatment for running sprint**
  - Where to look: Sprint Mgmt tab → sprint block that is currently running
  - Happy path: running sprint shows green glow border, flowing animated stripe, pulsing "LIVE" badge, live stat strip, shimmer progress bar, and per-ticket status indicators updating in real time
  - Edge cases: switching away from the Sprint Mgmt tab and back should restore animations; a sprint that finishes while viewed should transition from animated to completed state without a page reload
