# Roadmap phase 3 — advisor: suggest what to build next

**Date:** 2026-06-11
**Sprint label:** NEW
**Default labels:** enhancement
**Status:** drafted

CEO loop: "Commander suggests what to build next; I put the high-level
milestone there and sprints get planned ahead." Decisions: advisor runs once
a day; plans ahead 2–5 sprints at most. Depends on phase 1 (milestones) and
sprint 64 (briefs + to-dos); pairs with phase 2 (its output feeds the planner).

## Prompts

Paste one code block into the Bulk Create textarea. Prompts are `---`-separated.

```
Add an advisor agent that proposes what to build next, once a day. A Claude agent (Sonnet, subscription-funded like the other agents) runs once daily per project (and on demand via a button): it reads PRODUCT.md, the open milestones and their remaining tickets, the backlog, my to-do notes, recent sprint briefs, and rework/failure patterns from agent_runs, then produces 3 to 5 suggestions. Each suggestion has a one-line pitch, a short rationale grounded in what it read, a suggested milestone (existing or proposed new), and a rough scope (S/M/L). Suggestions are stored as drafts in the local DB — nothing is posted to GitHub. The daily run only happens when the dashboard is up; skip silently otherwise. Acceptance: each day I get a fresh, grounded set of 3 to 5 suggestions per project, visible without anything being created on GitHub.
---
Add a suggestions panel with accept and dismiss flows. The Roadmap tab shows current suggestions as compact cards (pitch, rationale, proposed milestone, scope). Accept sends the suggestion through the existing BA draft flow — the BA expands it into one or more proper tickets with acceptance criteria under the chosen milestone, which I review in the normal bulk-create review step before posting. Dismiss hides it and records it so the advisor does not re-suggest the same idea (pass dismissed pitches into its prompt as exclusions). Acceptance: accepting a suggestion lands reviewed BA-drafted tickets under the right milestone; dismissed ideas stay gone.
---
Let the advisor sketch a 2-to-5-sprint look-ahead. Alongside suggestions, the advisor maintains a short ordered look-ahead: which milestone slices the next few sprints should target, at most 5 sprints out, each entry one line with the tickets or themes it would pull. Display it on the Roadmap tab under the milestone cards. The phase-2 planner's "Plan next sprint" defaults to the look-ahead's first entry when one exists. This is advisory only — nothing is created until I plan and approve a sprint. Acceptance: the Roadmap tab shows a short ordered plan for the next few sprints, the planner picks it up as the default, and no GitHub objects are created by the look-ahead itself.
---
Put advisor output into the daily brief. The morning brief (sprint 64) gains a "suggested next" section: today's top suggestions one line each, plus the first look-ahead entry, each linking to the Roadmap tab to act on. Keep it to a glance — at most 5 lines. Acceptance: the morning brief ends with what Commander thinks I should build next, and one click takes me to where I can accept it.
```

## Notes

- Once-a-day cadence per decision; the on-demand button reruns within the day.
- Look-ahead capped at 5 sprints per decision — the advisor must refuse to
  plan deeper.
- The advisor never writes to GitHub; the only path to a real ticket is
  accept → BA draft → my review → post. Human stays in the loop everywhere.
- Cost note: one Sonnet call per project per day; inputs are local files +
  mirror reads, so no GitHub quota.
