## What Changed

Sprint 22 focused on hardening the running sprint card so it stays accurate
under label mutations, and enriching it with per-ticket agent metadata.

The sprint introduced a sprint-label lock that prevents `sprint-N` from being
stripped mid-run (#305), exposed the locked ticket snapshot in the `/live`
endpoint (#306), and wired the running card to read from that snapshot instead
of live GitHub labels (#307). On top of that, each in-flight ticket now shows
its active agent role tag, size pill, and elapsed time (#308), and a live log
panel displays the sprint's recent output with a 5-second refresh cycle (#309).

## What to Test

### Checklist

- [ ] **#305 — Sprint-label lock during run**
  - Where to look: start a sprint run, then manually remove its `sprint-N` label from any ticket via GitHub UI
  - Happy path: the ticket keeps its `sprint-N` label through to sprint completion; the label is not re-added but the guard prevents it from being removed
  - Edge cases: status transitions (`in-progress` → `sit`) must still work; `sprint-N` must survive them; only `in-progress`, `sit`, `uat`, and `needs-rework` may be added during the run

- [ ] **#306 — `/live` endpoint `issues[]` field**
  - Where to look: `GET http://localhost:8001/api/sprints/sprint-22/live?project=<name>` during an active run
  - Happy path: response includes a top-level `issues` array; each entry has `number`, `title`, `status`, `agent_status`, `agent`, `elapsed_secs`, and `size`
  - Edge cases: a ticket whose `sprint-N` label was manually stripped still appears in `issues[]`; pre-existing fields (`current_ticket`, `recent_log_lines`, `counts`, etc.) are unaffected

- [ ] **#307 — Running card bound to live snapshot**
  - Where to look: Sprint Mgmt tab → running sprint block during an active run
  - Happy path: all sprint tickets appear in the running card regardless of current label state; indicators (spinning ring, check, X, empty circle) animate correctly
  - Edge cases: stripping a `sprint-N` label mid-run must not remove the row from the card; no "No tickets in this sprint" message while the sprint is running

- [ ] **#308 — Agent tag, size pill, and elapsed time**
  - Where to look: Sprint Mgmt tab → running sprint block → in-flight ticket rows
  - Happy path: active ticket shows a purple `CODER` or amber `TESTER` tag; a coloured `S`/`M`/`L`/`XL` pill when size data is present; elapsed time formatted as `2m 13s`
  - Edge cases: pending and done tickets show no agent tag; tickets with no size data show no pill (no dash or placeholder)

- [ ] **#309 — Live log panel and post-run outcome band**
  - Where to look: Sprint Mgmt tab → running sprint block → log panel below the ticket list
  - Happy path: log panel shows `recent_log_lines` from `/live`; header shows a "live" indicator and `CODER · pid 1234` when an agent is active; auto-scrolls to newest line every 5 s
  - Edge cases: when the sprint finishes the log panel disappears and the outcome band shows Completed / Failed / Skipped totals; no tickets should disappear during the running → completed transition

## Notes

- #305–#307 form a layered stack: the label lock (#305) and API snapshot (#306) are prerequisites for the UI fix (#307). Test them in order.
- The `SIZE_MINUTES` JS constant introduced in #308 is a configurable placeholder for future stats-driven estimates; it drives no display logic in this sprint.
- The live log panel (#309) uses polling (`recent_log_lines`) at 5s, intentionally separate from the 2s indicator poll — do not consolidate them.
